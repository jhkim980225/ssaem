# 쌤 수업 잠금 프로그램 (ssaem-lock.exe)

PC실 실시간 수업(`/teacher/live`, `/live`)에서 **학생 PC를 진짜로 잠그는** 작은 윈도우 프로그램.
브라우저는 보안상 OS를 못 건드리니, 학생 수업 화면이 서버 검증을 마친 강사 명령을 이 프로그램에 넘긴다.

```
강사 화면 ──(서명된 명령, Supabase Realtime)──▶ 학생 수업 탭 ──(/api/live/verify 통과)──▶ 127.0.0.1:47800 ─▶ 잠금
```

## 동작

| 명령 | 화면 | 키보드·마우스 |
|---|---|---|
| `lock` | 모든 모니터를 네이비 화면으로 가림 (강사 문구 표시) | 막음 (포인터 이동만 허용) |
| `watch` | 그대로 — 학생 탭이 강사 화면을 꽉 채움. 위쪽에 안내 띠. 수업 탭 창(제목 = `win`)을 맨 앞으로 (1.2) | 막음 |
| `unlock` | 원래대로. lock에서 풀면 잠그기 전 맨 앞 창으로 포커스를 돌려줌 (1.2) | 풀림 |

강사 화면엔 버튼이 [잠금]/[해제]뿐 — 강사가 화면 공유 중이면 `watch`, 아니면 `lock`을 보내고, 공유를 켜고 끌 때 잠긴 학생을 자동으로 바꿔 건다.

- `GET /status`, `POST /beat`, `POST /cmd {"action","text","win"}` — 응답 `{"ok":true,"v":"1.2","mode":"…"}`.
  강사 카드는 v가 최신보다 낮으면 "잠금 프로그램 새로 받기"로 띄운다 (`AGENT_LATEST`, `src/lib/live.ts`)
- **감독 (1.1)**: `GET /activity` → 맨 앞 창 `{"app":"KakaoTalk","title":"…"}`, `GET /shot?w=480&q=60` → 화면 JPEG(모니터 전부).
  학생 수업 탭이 4초마다 받아 **강사 PC로 직접**(WebRTC 데이터 채널) 보낸다 — 서버를 안 거치고 저장도 안 한다.
  이 둘은 Origin 없는 요청(`<img src>` 등)을 거절한다
- 브라우저 요청은 **Origin이 등록된 쌤 주소일 때만** 따른다(403). 기본: 배포 주소 + `http://localhost:3000`.
  다른 도메인을 쓰면 exe 옆 `ssaem-lock.ini`에 `origin=https://…` 줄 추가.
- **안전장치**: 학생 탭의 `/beat`(5초마다)가 90초 끊기면 스스로 풀린다 — 네트워크·브라우저가 죽어 영영 잠기는 일 방지.
- 첫 실행 때 `HKCU\…\Run`에 등록 → 다음 로그인부터 자동 실행. 트레이에 방패 아이콘. 종료 메뉴는 일부러 없음.
- **자동 업데이트 (1.3)**: 켜고 20초 뒤, 그 뒤로 1시간마다 `/downloads/ssaem-lock.json`(`{"v","sha256"}`)을 본다.
  버전이 더 높으면 exe를 받아 **SHA-256이 맞을 때만** 바꿔 끼운다 — 실행 중인 exe는 덮어쓸 수 없지만 이름은
  바꿀 수 있어서 `ssaem-lock.exe.old`로 비키고 새 것을 같은 자리에 둔 뒤 `--updated`로 다시 켠다(새 프로세스가
  이전 것이 뮤텍스·포트를 놓을 때까지 기다림). 잠긴 동안엔 하지 않는다. 자동 실행 등록 경로가 그대로라 다음
  로그인에도 새 버전이 뜬다. exe가 있는 폴더에 쓰기 권한이 없으면(Program Files 등) 조용히 건너뛴다

## 한계

- **Ctrl+Alt+Del**은 윈도우가 어떤 프로그램도 못 막게 해 둔다 → 작업 관리자로 프로그램을 끌 수 있다.
  학생 계정을 표준 사용자로 두고 작업 관리자를 그룹 정책으로 막으면 거의 닫힌다.
- **서명 안 된 exe**라 내려받아 처음 실행하면 SmartScreen("Windows의 PC 보호")이 뜬다 → 추가 정보 → 실행.
  **스마트 앱 컨트롤**이 켜진 PC(윈도우 11 새로 설치한 PC 일부)는 아예 실행을 막는다 —
  설정 → 개인 정보 및 보안 → Windows 보안 → 앱 및 브라우저 컨트롤에서 끄거나, 코드 서명 인증서가 필요하다.
- 크롬·엣지 최신판은 웹페이지가 `127.0.0.1`에 접근할 때 "로컬 네트워크 접근" 허용을 한 번 묻는다.

## 빌드

`build.bat` — 윈도우 기본 .NET Framework 4 컴파일러(`csc.exe`, C# 5 문법)만 쓴다. 설치할 것 없음.
결과물: `public/downloads/ssaem-lock.exe` (강사 화면의 내려받기 링크) + `ssaem-lock.json`(`manifest.ps1`이
소스의 `Version`과 exe 해시로 만든다). **배포하면 학생 PC들이 1시간 안에 알아서 받으니**, 고칠 때마다
`Version`을 올리고 `AGENT_LATEST`(`src/lib/live.ts`)도 같이 올린다. 둘 다 커밋할 것 — json만 빠지면 아무도 안 받는다.

## 검증

자동 업데이트(1.3): `Version`을 1.2로, `Home`을 로컬 http 서버로 바꾼 사본을 띄워 1.2 → 1.3 교체·재실행·`.old` 정리,
해시가 틀린 json이면 그대로 1.2에 남는 것을 확인. .NET Framework `WebClient` + TLS 1.2로 배포 주소에서 받기 확인.

예전에 스마트 앱 컨트롤이 켜진 개발 PC에선 exe가 막혀서, 같은 소스를 PowerShell `Add-Type`으로 메모리에서 띄워 확인했다:
상태 조회 · 잘못된 Origin 403 · 사전 요청(Private-Network 헤더) · lock(한글 문구·따옴표) · watch 안내 띠 · unlock 화면 캡처.
