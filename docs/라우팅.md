# 라우팅

코드 실측 (2026-08-10, v0.4.0). 화면 가드는 `useGate()`(`src/components/RoleGuard.tsx`), API 가드는 `requireRole`/`requireUser`(`src/lib/auth.ts`).

## 접근 등급

| 등급 | 뜻 |
|---|---|
| 공개 | 로그인 불필요 |
| 로그인 | 로그인만 필요, 역할 무관 (`useGate("any")` / `requireUser`) |
| 학생 / 강사 / 원장 | 해당 역할만 (`useGate("student")` 등 / `requireRole`) |

**2단 방어**: 화면 가드는 편의, 실제 차단은 항상 서버. 화면을 우회해 API를 직접 불러도 401/403.

**3단 — RLS**: `NEXT_PUBLIC_SUPABASE_ANON_KEY`는 브라우저에 노출되므로 로그인 사용자가 PostgREST(`/rest/v1/...`)를 직접 부를 수 있다. 이 경로는 Next를 안 거쳐 위 가드가 전혀 적용되지 않는다. 그래서 클라이언트용 RLS 정책을 전부 제거해 anon/authenticated의 테이블 직접 접근을 차단했다(2026-08-11). 서버는 service_role이라 영향 없음. 검증: `npx tsx scripts/rls-check.ts` (6케이스).

`/teacher`만 `allowNoProfile` — 강사 가입 직후엔 아직 `profiles.role`이 없어서, 그 화면에서 프로필을 만들어야 하기 때문.

### 로그인 후 착지

`homeFor(role)` (`src/lib/role.ts`) — **서버 `profiles.role` 기준**. 로그인 탭에서 뭘 골랐는지는 안 본다.

| role | 착지 |
|---|---|
| `admin` | `/admin` |
| `student` | `/ask` |
| `teacher` 또는 프로필 없음 | `/teacher` |

### 렌더 순서 (깜빡임 방지)

`useGate()`가 아래 순서로 판정하고, **역할이 확정되기 전에는 본문을 절대 렌더하지 않는다**.

```
세션 조회 전        → 로딩 스켈레톤
세션 없음           → 로그인 안내 (또는 페이지가 넘긴 loginRender)
역할 조회 중        → 로딩 스켈레톤
역할 불일치         → "○○ 계정만 쓸 수 있어요" + 내 화면으로 가기 / 로그아웃
통과                → 본문
```

역할은 `Map<uid, Role>`에 캐시된다 — 같은 탭 안에서 페이지를 옮길 땐 `/api/profile`을 다시 부르지 않아 "로딩 스켈레톤" 단계가 건너뛰어진다. 탭을 새로 열면 캐시가 비므로 첫 진입만 스켈레톤을 거친다.

## API

### 공개

| 라우트 | 메서드 | 용도 |
|---|---|---|
| `/api/signup` | POST | 가입. `role=admin`은 개설 코드(`INVITE_CODE`) 필요 |
| `/api/join` | GET | 초대 코드 검증 (POST는 로그인 필요 — 수강 등록) |
| `/api/join-teacher` | GET | 강사 초대 코드 검증 |
| `/api/inquiry` | POST | 도입 문의 접수. 비로그인 원장이 쓰므로 공개 유지. IP당 분당 3회 |

### 로그인만 (`requireUser` → 미인증 401)

| 라우트 | 메서드 | 용도 |
|---|---|---|
| `/api/ask` | POST | 질문 → 스트리밍 답변. IP당 분당 20회 |
| `/api/teachers` | GET | 강사 목록 (`?academy=`). 초대받은 비공개 강사 포함 |
| `/api/courses?teacher=` | GET | 그 강사의 강좌 목록 (학생 필터 칩) |
| `/api/popular` | GET | 인기 질문 랭킹 + 강사별 비중. 2회 이상 반복된 것만 |
| `/api/related` | GET | 유사 질문 추천. IP당 분당 30회 |
| `/api/quiz` | GET | 문제 목록. **정답·해설 미포함** |
| `/api/quiz/attempt` | POST / GET | 채점(정답은 여기서만) / 오답노트 요약 |
| `/api/feedback` | POST | 답변 평가. 남의 대화면 403 |
| `/api/profile` | GET / POST | 내 프로필 조회 / 저장. POST는 이미 강사거나 프로필이 없을 때만 통과 |
| `/api/conversations` | GET | 내 대화 목록·상세. 학생은 내 대화, 강사는 내가 받은 질문 |
| `/api/join` | POST | 수강 등록 |

### 강사 (`requireRole(req, "teacher")` → 401/403)

| 라우트 | 메서드 | 용도 |
|---|---|---|
| `/api/documents` | GET / POST / PATCH / DELETE | 자료 CRUD (수정 시 재청킹) |
| `/api/documents/events` | GET | 자료 감사 이력 |
| `/api/upload` | POST | PDF 업로드 (15MB, 매직 바이트 검사) |
| `/api/courses` | GET(무param) / POST / DELETE | 내 강좌 목록·생성·삭제 |
| `/api/quiz/generate` | POST / GET / DELETE | 문제 출제·목록·삭제. 말투 자료(`kind='style'`)는 400. 강사당 분당 5회 |
| `/api/insights` | GET | 인사이트 집계 |
| `/api/students` | GET | 학생별 리포트 |
| `/api/students/reset-password` | POST | 학생 임시 비밀번호 발급. 강사당 시간당 10회 |
| `/api/invite` | GET | 학생 초대 QR·링크 |

### 원장

| 라우트 | 메서드 | 용도 |
|---|---|---|
| `/api/admin` | GET | 학원 통계·강사 목록·초대 링크 |
| `/api/admin` | PATCH | 강사 공개/숨기기 토글 |

`/api/admin`은 `userFromRequest` + 조회한 `profiles.role`로 원장 여부를 직접 판정한다 (학원·강사 정보를 어차피 같은 쿼리로 가져오기 때문).

## 소유권 (역할과 별개)

역할이 맞아도 남의 데이터는 못 본다. 서버 쿼리에서 강제:

- 자료·강좌·문제: `eq("teacher_id", uid)`
- 대화 이어가기(`/api/ask`): `conv.student_id === uid` 아니면 무시하고 새 대화로 분리
- 피드백: 대화 주인이 아니면 403
- 학생 비밀번호 발급: 같은 학원 + (내 수강생이거나 나에게 질문한 학생)
