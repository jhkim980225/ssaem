# 라우팅

코드 실측 (2026-10-15, v0.60.0 — 페이지 29·API 42). 화면 가드는 `useGate()`(`src/components/RoleGuard.tsx`), API 가드는 `requireRole`/`requireUser`/`userWithRole`(`src/lib/auth.ts`). 기능별 상태는 `구현내역서.md`.

## 접근 등급

| 등급 | 뜻 |
|---|---|
| 공개 | 로그인 불필요 |
| 로그인 | 로그인만 필요, 역할 무관 (`useGate("any")` / `requireUser`) |
| 학생 / 강사 / 원장 / dev | 해당 역할만 (`useGate("student")` 등 / `requireRole`) |

**2단 방어**: 화면 가드는 편의, 실제 차단은 항상 서버. 화면을 우회해 API를 직접 불러도 401/403.

**테넌트 경계**: 역할이 맞아도 **남의 학원 데이터는 못 본다**. 강사 uuid를 받는 라우트(`ask`·`popular`·`related`·`quiz`·`quiz/attempt`·`courses?teacher=`·`lessons`·`board`·`assessments`·`reviews`·`submissions`)와 `teachers` 목록은 `sameAcademy()`(`src/lib/tenant.ts`)로 호출자 학원과 일치를 강제한다(불일치면 404 또는 빈 목록). 이름으로 찾는 라우트(`bank/records?name=`·`bank/stats`)는 `academyOf()`로 같은 학원만. 검증: `npx tsx scripts/tenant-check.ts`.

**학생 노출 = 수강 연결 기준**: teachers·courses·lessons·board는 학생에게 **수강 연결(enrollments)된 것 + 공용(course_id null)**만 준다. 강사·원장은 학원 전체.

**3단 — RLS**: `NEXT_PUBLIC_SUPABASE_ANON_KEY`는 브라우저에 노출되므로 로그인 사용자가 PostgREST(`/rest/v1/...`)를 직접 부를 수 있다. 이 경로는 Next를 안 거쳐 위 가드가 전혀 적용되지 않는다. 그래서 클라이언트용 RLS 정책을 전부 제거해 anon/authenticated의 테이블 직접 접근을 차단했다(2026-08-11). 서버는 service_role이라 영향 없음. 검증: `npx tsx scripts/rls-check.ts`.

### 로그인 후 착지

`homeFor(role)` (`src/lib/role.ts`) — **서버 `profiles.role` 기준**. 로그인 탭에서 뭘 골랐는지는 안 본다.

| role | 착지 |
|---|---|
| `admin` | `/admin` |
| `student` | `/ask` |
| `teacher` 또는 프로필 없음 | `/teacher` |
| `dev` | `/dev` |

### 렌더 순서 (깜빡임 방지)

`useGate()`가 `lib/auth-store.ts`의 스냅샷을 읽어 아래 순서로 판정한다. **역할이 확정되기 전에는 본문을 절대 렌더하지 않는다.**

```
status=loading 또는 role=undefined  → 본문 스켈레톤
status=signed-out                   → 로그인 안내 (또는 페이지가 넘긴 loginRender)
역할 불일치                          → "○○ 계정만 쓸 수 있어요"
통과                                 → 본문
```

**인증 상태는 모듈 스토어 1곳에 있다** (탭당 1개, 라우트 이동으로 초기화되지 않음). 그래서 한 번 확정된 뒤에는 어떤 페이지로 옮겨도 **첫 렌더부터 확정된 값을 동기로 읽는다** — 이동 시 스켈레톤이 아예 안 나온다. 새 탭·새로고침에서만 한 번 거친다. 로그인은 7일 후 자동 만료.

헤더도 같은 스토어를 읽는다. `loading` 동안에는 비로그인 내비를 그리지 않고 **고정폭 자리만 잡는다** — 여기서 "로그인" 버튼을 그리면 로그인한 사용자에게 로그인 버튼이 한 번 번쩍인다.

자세한 배경은 `docs/인증-로직.md`의 "인증 상태는 lib/auth-store.ts 한 곳에만 있다" 절.

## 소유권 (역할과 별개)

역할이 맞아도 남의 데이터는 못 본다. 서버 쿼리에서 강제:

- 자료·강좌·문제·게시물·평가: `eq("teacher_id", uid)`
- 대화 이어가기(`/api/ask`): `conv.student_id === uid` 아니면 무시하고 새 대화로 분리
- 피드백: 대화 주인이 아니면 403
- 시험 기록 상세: `user_id === uid` 아니면 404
- 과제 현황: 강좌 주인 강사만
- 학생 비밀번호 발급: 같은 학원 + (내 수강생이거나 나에게 질문한 학생)
