# 자료 파이프라인

등록 흐름: 원본 저장 → 청킹 → 배치 임베딩 → chunks 저장 → 감사 로그.

## 문서 CRUD — /api/documents (src/lib/documents.ts)

- `GET`: 내 문서 목록 + 청크 수. 텍스트 자료는 수정 프리필용 원문 포함 (PDF는 제외).
- `POST`: 텍스트 등록 → `saveDocument()`.
- `PATCH`: 텍스트 수정 → `updateDocument()` — 원문 교체 → 기존 청크 전체 삭제 → 재청킹·재임베딩. PDF는 거부("재업로드로 수정하세요").
- `DELETE`: 삭제 전 제목·종류·청크 수 확보(지운 뒤엔 못 읽음) → 삭제(청크 cascade) → 감사 로그.

## PDF 업로드 — POST /api/upload

- `runtime = "nodejs"`. unpdf(`getDocumentProxy` + `extractText`)로 텍스트 추출.
- PDF 아니면 400. 추출 결과 빈 문자열(스캔 PDF)이면 OCR 폴백 → 그래도 없으면 422 + 안내.
- 추출 텍스트로 `saveDocument()` — 텍스트 등록과 동일 경로.

## 스캔 PDF OCR — src/lib/ocr.ts

- LLM 비전으로 텍스트 추출. `GEMINI_API_KEY`(무료, inline_data) → `ANTHROPIC_API_KEY`(document block) → `null`.
- PDF 통째 base64 1콜, 15MB 상한. 아주 긴 스캔본은 max_tokens에 잘림 (필요 시 페이지 배치로 승격).

## 청킹 — src/lib/chunk.ts

- 문단(`\n{2,}`) → 문장(마침표/줄바꿈 경계) → 하드 char 컷 순서로 분할 후 그리디 병합.
- 기본 size 800 / overlap 150 (한국어 기준 char ≈ token 근사).
- overlap은 앞 청크 꼬리를 다음 청크 머리에 덧붙이는 방식.

## 임베딩 — src/lib/embed.ts

- 우선순위: `OPENAI_API_KEY`(text-embedding-3-small) → `GEMINI_API_KEY`(gemini-embedding-001) → `null`.
- 차원 `vector(1536)` 고정. Gemini는 3072 기본을 `outputDimensionality: 1536`으로 축소(MRL) 후 정규화.
- `embedMany()`: 문서 등록/수정 시 청크 전체 배치 1콜.
- SDK 없이 fetch 직접 호출. 프로바이더 교체는 이 파일만 수정.

## 감사 로그 — document_events

- `logDocumentEvent()`: 등록=created, 삭제=deleted, 수정=deleted+created 쌍 (action check 제약에 updated 없음 — 마이그레이션 회피).
- try/catch로 감싸 로그 실패가 본 작업(등록/삭제)을 막지 않음.
- 조회: `GET /api/documents/events` (기본 30, max 100).
