## 1. 문제 유출 차단 (복사·붙여넣기) — ⚠️ 대부분 됨

v0.11.11 `src/components/StudentProtection.tsx` (루트 레이아웃 마운트, **role=student일 때만**).

| 항목 | 상태 | 근거 |
|---|---|---|
| 복사(Ctrl+C)·잘라내기 차단 | ✅ | `copy`·`cut` preventDefault |
| 텍스트 선택 차단 | ✅ | `selectstart` + CSS `user-select:none` |
| 드래그앤드롭(끌어내기) 차단 | ✅ | `dragstart` + `-webkit-user-drag:none` |
| 우클릭 메뉴 차단 | ✅ | `contextmenu` |
| 이미지 저장 차단 | ✅ | 우클릭+드래그 차단, iOS `touch-callout:none` |
| 워터마크(추적) | ✅ | 학생 아이디+uid 반투명 반복 — 유출본 추적용 |
| 입력창 예외(질문·답안 타이핑) | ✅ | `isEditable()`로 input/textarea 제외 |
| **붙여넣기(paste) 차단** | ❌ | `paste` 이벤트 미차단 — 아래 참고 |
| **스크린샷 차단** | ❌ **불가** | 웹 API 없음. OS 캡처·타 기기 촬영 못 막음 |

**붙여넣기 관련 정리**: 붙여넣기는 *밖에서 안으로* 넣는 동작이라 **문제 유출 경로가 아니다**(유출은 복사가 핵심 — 이미 차단됨). 다만 평가·시험에서 **학생이 답을 밖에서 긁어와 붙여넣는 부정행위**를 막으려면 별도로 `paste` 차단이 필요하다. 원하면 추가.

**한계 명시**: 스크린샷은 웹에서 원천 차단 불가(네이티브 앱 FLAG_SECURE 영역). 현재 방식은 "긁어가기 수고↑ + 워터마크로 추적 가능"한 억제책.

## 2. 평가 시 본인 인증 (로그인·전자서명) — ⚠️ 로그인만 / ❌ 전자서명 없음

| 항목 | 상태 | 근거 |
|---|---|---|

| **이메일 인증** | ❌ | `signup/route.ts:102` `email_confirm: true` = **메일 인증 생략** |

| **전자서명** | ❌ | 저장소 전체에 서명 기능 없음(`서명` 히트는 초대코드 HMAC뿐) |

**현재 본인 인증 수준 = 아이디/비밀번호뿐.** 계정 공유하면 대리 응시를 막을 수단이 없다. 평가 신뢰성을 원하면 최소 아래 중 하나 필요:
- **전자서명(캔버스 손글씨)** — 응시 직전 서명 받아 이미지로 저장 + 시트에 기록. 법적 효력보다 "본인이 응시했다는 확인·심리적 억제"용. 구현 쉬움(외부 의존 없음)
- **이메일/SMS 인증코드** — 응시 시작 시 1회용 코드. 외부 서비스(메일·SMS) 필요
- **응시 IP·기기 기록** — 보조 지표

|---|---|---|

| **평가 세트 업로드·응시** | ❌ | `docs/superpowers/specs/2026-08-16-평가세트-구글시트-design.md` **스펙만 확정**, 코드 0줄 (`src/app/api/assessments` 없음, 테이블 없음) |
| 응시 1회 제한 | ❌ | 스펙에 설계됨(unique 제약), 미구현 |
| **전자서명 수집** | ❌ | **스펙에도 없음** — 이번 요청으로 신규 추가 필요 |
| **구글시트 append** | ❌ | 스펙에 설계됨(서비스계정+JWT), 미구현. 사용자 요청으로 **보류 중** |

**현재 상태**: 구글시트 구현은 사용자 지시로 보류. 재개하면 구현 계획부터.

## 4. 원장 계정 — ⚠️ 통계는 충실 / ❌ 수강평 없음

### 지금 되는 것 (`/admin`)
- 기간 선택(7·30·90일), 학원명·플랜 배지, 학생 초대 URL
- 요약: 등록 자료 수, 학생 질문 수, **활동 학생 비율**, 답변 평가 도움됨/아쉬움
- 누적 답변 → "조교 N시간 분량" 환산, 오늘 질문 사용량/한도
- 일별 질문 그래프
- **학생 목록**: 학원 전체 학생 이름 + 질문 수 + 마지막 질문 시점("미사용" 배지)
- **확인 필요 답변** 10건: 👎 받은 질문·답변 200자·강사명
- **강사 목록**: 과목·자료수·질문수·도움됨/아쉬움 + **공개/숨기기 토글**
- 강사 초대 QR·링크

### ❌ 수강평(강사·수업 평가) — 존재하지 않음
- 스키마 17개 테이블 중 **강사/수업 평가 테이블 없음**
- `message_feedback`는 **AI 답변 1건 단위 평가**(PK=message_id, 작성자 컬럼조차 없음, 도움됐어요/아쉬워요 2지선다). 원장 화면의 "도움됨/아쉬움"은 전부 이 값 집계
- **즉 원장은 "학생이 강사를 어떻게 평가했는지"를 볼 수 없다.** AI 답변 품질 지표만 강사별 합산해서 본다

### ❌ 학생 정보 — 이름·질문수뿐
- `profiles` 컬럼 = `id, academy_id, role, name, created_at`. **전화·이메일·보호자·학년 컬럼 자체가 없음**
- 학생 상세 화면 없음(목록 표시만), 대화 열람 불가(당사자만 → 원장은 항상 404)

### ❌ 원장이 못 하는 것 (코드 검증)
강사 자료·인사이트·이력 열람(403), 강사 제거(숨기기만), 학생 제명, 학원명·slug 수정, 플랜 전환(운영자 SQL), 강사 프로필 편집, 학생 초대코드 발급(강사 초대만).

**요청하신 "수강평·정보"는 둘 다 신규 개발 대상.**

## 5. 채팅 AI 답변 — ✅ 구현됨 (한계 있음)

| 항목 | 상태 | 비고 |

| 강사 자료 한정 검색 | ✅ | `match_chunks` 벡터(top-5) + 강좌 필터, 말투자료 제외 |
| 근거(출처) 표시 | ⚠️ | `X-Sources` 헤더로 **60자 미리보기만**. 문서 제목·페이지 번호 없음 |
| 대화 이력 이어가기 | ✅ | 직전 10턴 컨텍스트, `X-Conversation-Id` |
| 중단 | ✅ | AbortController + ■ 버튼, 부분 답변 유지 |
| 재시도 | ⚠️ | 전용 버튼 없음 — 실패 시 질문이 입력창에 복원되어 수동 재전송 |
| 강사 말투 반영 | ✅ | `tone_note` → 시스템 프롬프트 |
| 폴백 체인 | ✅ | 답변 Claude→Gemini(429 시 lite), 임베딩 OpenAI→Gemini→키워드 |
| 마크다운 렌더 | ⚠️ | 자체 구현 — 굵게·코드·표·불릿만. 링크·번호리스트 미지원 |

**알려진 한계 (코드 근거)**
- **유사도 임계값 없음** — 무관한 자료도 무조건 top-5가 근거로 들어감
- **자료 0건이면 일반 지식으로 답변** — "선생님 자료에서만 찾아요" UI 문구와 어긋남
- **Anthropic 장애 시 Gemini로 안 넘어감** — 키 유무로만 분기(429는 Gemini 내부만 폴백)
- **답변 실패 시 학생 질문도 미저장** — 이력에 안 남고 한도 집계에도 빠짐
- **중단해도 서버는 계속 생성** — 토큰 비용 발생, 부분 답변 DB 저장
- max_tokens 1200 고정(긴 답변 잘림, 알림 없음), 컨텍스트 10턴 고정, 레이트리밋 인메모리(다중 인스턴스 취약)
- 과거 대화 복원 시 출처가 안 붙음

## 6. 문서 인식 — ⚠️ PDF만

| 형식 | 상태 | 근거 |
|---|---|---|
| 텍스트 붙여넣기 | ✅ | 20만자 상한 |
| PDF (텍스트 레이어) | ✅ | `unpdf` 추출 |
| PDF (스캔·이미지) | ⚠️ | LLM 비전 OCR — **Pro 플랜 전용**(무료는 403) |
| 이미지 PNG/JPG | ❌ | MIME 검사에서 400 |
| 워드 .docx | ❌ | 파서 의존성 자체 없음 |
| 한글 .hwp/.hwpx | ❌ | 없음 |
| 엑셀·CSV | ❌ | 없음 (`xlsx`는 평가 스펙 문서에만 등장) |
| PPT | ❌ | 없음 |

**처리 흐름**: 업로드(15MB·30회/시간) → PDF 매직바이트 검사 → unpdf 추출 → 비면 OCR(Pro·10회/시간) → 청킹(800자/overlap 150) → 배치 임베딩 → 저장. 실패 시 문서 행 롤백(유령 문서 방지).

**알려진 한계**
- **부분 스캔 PDF는 OCR을 안 탄다** — 전체 텍스트가 *완전히* 비어야만 OCR. 표지 1p만 텍스트고 나머지 50p 스캔이면 **1p만 저장되고 조용히 성공**
- **OCR은 PDF 통째 1콜** — 긴 스캔본은 토큰 상한에서 잘리고 **잘렸다는 신호 없음**
- OCR 429 폴백 없음(답변 쪽엔 있음), OCR 우선순위가 답변과 반대(OCR=Gemini 우선, 답변=Claude 우선)
- `/api/upload`에 maxDuration 미설정 — 대용량 PDF는 함수 타임아웃 위험
- 임베딩 실패 시 null 벡터 저장 → 벡터 검색에서 영구 제외(키워드로만 잡힘)
