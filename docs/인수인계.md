## 반드시 알아야 할 설계 결정

1. **학생 노출 규칙 = enrollment 기준**: teachers·courses·lessons·board 전부 "수강 연결된 것 + 공용(course_id null)"만. 강사·원장은 전체. 새 학생-facing API도 이 규칙 따를 것.
2. **DB 마이그레이션은 DATABASE_URL로 직접 적용 가능** — SQL editor 수동 불필요. 패턴: `supabase/migrations/*.sql` 작성 → pg Client로 실행하는 임시 tsx 스크립트 (이번 세션에 visit_days·dev role·documents.summary·submissions·board_posts 전부 이렇게 적용됨). CLAUDE.md의 "SQL editor 수동" 문구는 구식.
3. **실무 문항 소스 한계**: 확정답안 PDF 있는 16회차(108·111~125)만 실무 추출 가능(구회차 HWP 답안 번호 소실). 전산세무1급은 원본 데이터 0건 — 분류 규칙은 "전산세무" prefix라 데이터만 오면 자동 적용.
4. **재적재 절차**: acct_quiz에서 `PYTHONIOENCODING=utf-8 python parse_questions.py` → acct_rag에서 실무만 지우고 `npx tsx scripts/import-bank.ts` (upsert 키 = source,stem). 실무 삭제 시 bank_attempts가 cascade로 같이 지워짐.
5. **e2e의 무료 한도 우회 패턴**: test 강사(무료 10건 초과)는 academies.plan을 잠시 'pro'로 올렸다가 원복 (e2e 내 2곳 — 수업 달력·과제 섹션).
6. **dev 역할**: profiles.role 제약에 'dev' 추가됨. dev/dev 로그인 → /dev 착지, 대시보드 자체 로그인 폼(일반 /login 안 씀). `/api/dev/metrics`는 dev만.
7. **JournalEntry**: 이어지는 계정 줄의 차/대 판정은 대차평형(합 일치 유일해)으로 — 계정명 규칙 하드코딩 금지(할인발행 상계 케이스 존재). 복수 해면 원문 폴백(43건).
8. **접속 핑**: sessionStorage 가드(세션당 1회), KST 날짜, 학생 role만 기록.
9. **커밋 규칙**: 버전 bump(package.json→푸터 표시) + `docs/작업내역.md` 항목 + `Co-Authored-By: Claude Fable 5` + 즉시 push (승인 불필요 — 메모리 규칙).

## 알려진 문제·백로그

- **Discord 알림**: 설계 합의됨(하루 첫 접속·CBT 채점·과제 제출·신규 가입, 웹후크 방식). **사용자의 DISCORD_WEBHOOK_URL 대기 중** — URL 받으면 `lib/notify.ts` + 라우트 4곳 한 줄씩.
- **문제은행 단독 배포**: "같은 repo + 별도 Vercel 프로젝트 + BANK_ONLY 플래그 + 익명 풀이 허용" 안으로 제안됨. **한국세무사회 기출 저작권 확인이 선행 조건** — 사용자 확인 대기.
- 대화 말풍선에 마크다운 원문(`**`, 표) 노출 — 개편 전부터 있던 이슈, 미처리.
- `POST /api/documents`가 title 파라미터 무시(제목=본문 앞 40자) — 관찰만 함.
- e2e를 서버 재시작 없이 연속 2회 돌리면 "문의 필수값 검증" 1건이 inquiry 레이트리밋(분당 3회) 때문에 flaky — 제품 버그 아님.
- 과제는 텍스트만 — 사진(KcLep 캡처) 제출은 스토리지 확장 여지.

## 운영 노트 (다음 세션 시간 절약)

- dev 서버가 API 전부 404를 뱉으면 `.next` 잔재 충돌 — `rm -rf .next` 후 재기동.
- gstack browse로 UI 자동화 시 **React 버튼은 실클릭(@ref)만 등록됨** — `js el.click()` 불가. 로그인 세션은 서버 재시작마다 날아가므로 매번 재로그인.
- 테스트 계정: 학생 st/st (김대차 기본반), test3(준혁T 전산회계1급), 강사 test/test(김대차), dev/dev. 준혁T(jhkim@ssaem.kr)는 사용자 본인 실계정 — 매직링크로 토큰 발급 가능하나 데이터 흔적 남기지 말 것.
