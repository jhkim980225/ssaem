# 평가 세트 업로드 + 결과 구글시트 저장 — 설계

작성 2026-08-16. 상태: 승인됨(브레인스토밍). 다음 단계: 구현 계획(writing-plans).

## 목표

강사가 **평가문제(4지선다)를 엑셀/CSV로 업로드**해 이름 붙은 **평가 세트**를 만들고,
학생이 그 평가를 풀면 결과를 **DB에 저장 + 구글시트에 한 줄씩 append**한다.

## 확정 결정 (브레인스토밍)

| 항목 | 결정 |
|---|---|
| 문제 형식 | 4지선다 객관식만 (서버 자동 채점, 기존 answer 0-based 로직 재사용) |
| 업로드 | 엑셀(.xlsx)/CSV 파일. SheetJS로 파싱(한글 cp949/UTF-8 자동 처리) |
| 단위 | 이름 붙은 '평가 세트'(assessment) — quiz와 분리된 새 개념 |
| 시트 저장 | 학생 제출 즉시 한 줄 append |
| 응시 | **1회 제한** (재응시는 강사 초기화 필요 — 후속) |
| 시트 대상 | **환경변수로 지정한 시트 하나**로 시작 (학원별 분리는 후속) |
| 학생 진입 | 기존 `/quiz`에 **'평가' 필터**로 (새 페이지 안 만듦) |
| 시트 인증 | 서비스 계정 (사용자 로그인 불필요) |
| **본인 확인** | 로그인 계정 + **전자서명**(응시 전 캔버스 손글씨) — 2026-08-18 추가 |

## 전자서명 (2026-08-18 추가, 선행 구현 완료)

평가 응시의 본인 확인을 로그인만으로 두면 계정 공유 시 대리 응시를 막을 수 없다.
응시 **시작 전** 손글씨 서명을 받아 기록한다. 법적 전자서명이 아니라 본인 확인·억제·사후 대조용.

이미 구현된 것(B, v0.11.12):
- `src/components/SignaturePad.tsx` — 캔버스 손글씨 패드(포인터 이벤트, DPR 대응, 지우기). 외부 의존 없음
- `src/lib/signature.ts` — PNG dataURL 형식·크기·빈 서명 검증 (`checkSignature`, `looksBlank`)
- `POST/GET /api/signature` — 저장·본인 조회. IP·User-Agent 함께 기록. 조회 응답에 이미지 원문 미포함
- `signatures` 테이블 (`kind` + `ref_id` 범용 설계, 마이그레이션 `20260818000000_signatures.sql`)
- 검증: `scripts/test-signature.ts` 12케이스 + e2e 전자서명 구간(테이블 있으면 실행)

A(평가) 구현 시 연결 방법:
1. 응시 화면에서 `SignaturePad`로 서명 받기 → 없으면 제출 버튼 비활성
2. `POST /api/assessments/<id>/submit`에 `signature`(dataURL) 동봉
3. 서버가 attempt 저장 후 `signatures`에 `kind='assessment'`, `ref_id=<attempt.id>`로 기록
4. 시트 행에 **로그인 아이디·서명 시각**을 추가 (서명 이미지 자체는 시트에 넣지 않는다 — DB 보관)

## 비목표 (YAGNI — 이번 범위 아님)

- 실무 자가채점·주관식·서술형 평가
- 학원별 개별 시트 설정 UI (env 하나로 시작)
- 재응시/응시 초기화 UI
- 평가 기한(마감시각)·시간제한 타이머
- 평가 결과 대시보드(강사용 집계 화면) — 시트가 그 역할

## 데이터 모델 (새 테이블 4개, `quiz_*` 불변)

```sql
create table assessments (
  id uuid primary key default gen_random_uuid(),
  teacher_id uuid not null references profiles(id) on delete cascade,
  course_id uuid references courses(id) on delete set null,   -- null = 그 강사 전체 학생
  title text not null,
  created_at timestamptz default now()
);
create index assessments_teacher_idx on assessments(teacher_id, created_at desc);

create table assessment_questions (
  id uuid primary key default gen_random_uuid(),
  assessment_id uuid not null references assessments(id) on delete cascade,
  ord int not null default 0,
  question text not null,
  choices jsonb not null,              -- ["보기1","보기2","보기3","보기4"]
  answer int not null check (answer between 0 and 3),
  explanation text
);
create index assessment_questions_set_idx on assessment_questions(assessment_id, ord);

create table assessment_attempts (
  id uuid primary key default gen_random_uuid(),
  assessment_id uuid not null references assessments(id) on delete cascade,
  student_id uuid not null references profiles(id) on delete cascade,
  score int not null,
  total int not null,
  synced boolean not null default false,   -- 시트 append 성공 여부 (재전송용)
  submitted_at timestamptz default now(),
  unique (assessment_id, student_id)       -- 1회 제한
);
create index assessment_attempts_student_idx on assessment_attempts(student_id, submitted_at desc);

create table assessment_responses (
  id uuid primary key default gen_random_uuid(),
  attempt_id uuid not null references assessment_attempts(id) on delete cascade,
  question_id uuid not null references assessment_questions(id) on delete cascade,
  chosen int not null check (chosen between 0 and 3),
  correct boolean not null
);
create index assessment_responses_attempt_idx on assessment_responses(attempt_id);
```

- RLS: 클라이언트 정책 없음(=service_role만) — 기존 테이블과 동일 규칙.
- 스키마는 `supabase/schema.sql` 갱신 + 마이그레이션 파일 신규.

## 업로드 흐름 (강사)

1. `/teacher`에 "평가 만들기" 섹션: 제목 입력 + 반 선택(선택) + 파일 업로드
2. `POST /api/assessments` (multipart): 파일 파싱 → assessment + assessment_questions 저장
3. 파서: **SheetJS(`xlsx`)** — `.xlsx`·`.csv` 모두, 인코딩 자동.
   - 양식 컬럼(헤더 1행 필수): `문제 | 보기1 | 보기2 | 보기3 | 보기4 | 정답 | 해설`
   - `정답`은 1~4(1-based) 입력받아 0-based로 저장
   - 형식 깨진 행(보기 4개 미만/정답 범위 밖/문제 공백)은 버리고 `{created, skipped}` 반환
   - 양식 파일 다운로드 버튼: 클라에서 SheetJS로 즉석 생성(정적 파일 관리 안 함)
4. 상한: 문항 200개, 파일 2MB, 문제·보기 각 500자 초과분은 절단. 무료 플랜 한도 정책은 후속(일단 무제한).
5. 라우트 가드: `requireRole("teacher")` + 소유권(course_id는 `ownCourseOrNull`).

## 응시 + 저장 흐름 (학생)

1. `/quiz`에 **평가 필터**: 강사 선택 시 그 강사의 배정 평가 목록 노출
   - `GET /api/assessments?teacher=<uuid>` — 호출자 역할로 분기: 학생은 내 학원·강사 배정 평가만(`sameAcademy`, 이미 응시 건은 "완료" 표시), 강사는 본인 소유 평가 목록(관리용)
2. 풀기: `GET /api/assessments/<id>/questions` — **정답·해설 미포함**(채점 전 노출 차단, quiz와 동일 원칙)
3. 제출: `POST /api/assessments/<id>/submit` `{ answers: [{questionId, chosen}] }`
   - 서버 채점 → **① DB 저장(attempt+responses, 원천)** → **② 구글시트 append**(best-effort)
   - 이미 응시(unique 위반)면 409 "이미 응시한 평가예요"
   - 응답: 점수·총점·문항별 정오·해설
4. 시트 한 줄: `제출시각 | 학원명 | 강사명 | 평가명 | 학생명 | 로그인아이디 | 서명시각 | 점수 | 총점 | 정답률 | 문항별정오(예: OXOOX)`
   (서명 이미지 원본은 시트에 넣지 않고 `signatures` 테이블에 보관 — 개인정보·용량)

## 구글시트 연동 (`src/lib/sheets.ts` — 격리 모듈)

- **서비스 계정 + JWT**: `google-auth-library`로 RS256 JWT 서명→액세스 토큰, Sheets REST `spreadsheets.values.append`를 **fetch**로 호출. (전체 `googleapis` SDK 대신 가벼운 조합 — Gemini를 fetch로 부르는 기존 프로바이더 격리 패턴과 일치)
- env: `GOOGLE_SA_EMAIL`, `GOOGLE_SA_PRIVATE_KEY`(개행 `\n` 이스케이프), `GOOGLE_SHEET_ID`, `GOOGLE_SHEET_TAB`(기본 `결과`)
- 셋업: 대상 시트를 `GOOGLE_SA_EMAIL`에 **편집자 공유**
- **단계적 강등**: env 미설정이면 `appendResultRow`가 no-op 반환 → 기능은 DB까지 정상. (키 없으면 기능 낮추는 이 코드베이스 규칙)
- **best-effort**: append 실패(네트워크·쿼터·권한)해도 응시 결과·응답엔 영향 없음. 실패 시 `attempts.synced=false`로 남겨 나중 재전송 스크립트(`scripts/resync-sheets.ts`)로 밀어 넣기. (`message_citations` 기록 실패가 답변에 무영향인 패턴)

## 에러·엣지 케이스

| 상황 | 처리 |
|---|---|
| 시트 env 없음 | append no-op, DB만 저장 (기능 유지) |
| append 실패 | synced=false, 로그, 결과는 정상 반환 |
| 중복 응시 | unique 제약 + 409 |
| 타 학원/타 강사 평가 접근 | `sameAcademy` 게이트 → 404 |
| 문항 0개 평가 응시 | 400 차단 (업로드 시 0문항이면 생성 거부) |
| CSV 인코딩(cp949) | SheetJS가 처리, BOM strip |
| 정답 범위 밖·보기 부족 행 | 업로드 시 버리고 skipped 카운트 안내 |
| 문제/보기 초장문 | 500자 초과분 절단(거부 안 함) |
