# 구현내역서 — 학원 AI 튜터

**버전** 2.1 · **기준일** 2026-10-15 · **앱** v0.60.0 · **작성 근거** 코드 실측(페이지 29·API 42 전수) + `작업내역.md` + 실DB 집계

| 항목 | 내용 |
|---|---|
| 서비스 | 학원 전용 AI 조교. 강사가 자료를 등록하면 학생이 그 강사를 골라 질문하고 **그 강사 자료를 근거로** 답변을 받는다. 여기에 강좌 ROOM 수업 관리와 기출 문제은행(4,806문항)이 붙는다 |
| 범위 | 웹앱(PWA) 전 기능. 결제(PG)·모바일 네이티브 앱은 범위 밖 |
| 관련 문서 | 화면·API 접근 등급 `라우팅.md` / 인증 `인증-로직.md` / DB `db-design.md` / 문제은행 적재 `문제은행-적재-규칙.md` / 현행 법령 `법령-참고자료.md` / 고객용 소개 `프로젝트-소개-클라이언트.md` / 변경 이력 `작업내역.md` |

> 2026-10-15 이 문서 하나로 통합했다 — 옛 `기능정의서.md`(v1.2) · `기능-명세.md` · `권한별-구현현황.md` · `구현-체크리스트.md` · `구현내용/` · `기능정의/`는 git 이력에 있다.
> 기능을 추가·변경하면 해당 표에 행을 넣고 머리의 기준일·버전을 갱신한다.

## 1. 용어

| 용어 | 정의 |
|---|---|
| 학원 | 과금·격리 단위(테넌트). 원장 1명이 개설 |
| 강사 | 자료를 등록하고 자기 이름의 튜터를 갖는 사용자 |
| 강좌 ROOM | 강좌(반). 자료·수강생·초대 코드·수업 달력의 단위. 강좌 미지정 자료 = **공용**(모든 ROOM 검색에 포함) |
| 수강 연결 | `enrollments`(학생 × 강좌). 학생에게 보이는 강사·ROOM·수업·게시물은 전부 이것 + 공용 기준 |
| 자료(document) | 강사가 올린 원본 텍스트/PDF. 보존되며 수정 시 원본에서 재청킹 |
| 수업 자료 | 수업 날짜(`lesson_date`)가 지정된 자료. 수업 달력·AI 요약·과제 제출의 단위 |
| 청크(chunk) | 자료를 검색 단위로 쪼갠 조각 + 임베딩 |
| 근거 | 답변 생성에 쓰인 청크. 학생에게 출처로 노출 |
| 공용 참고자료 | `teacher_id IS NULL` 문서. 현행 법령 원문. 강사 자료와 따로 검색해 2건만 덧붙인다 |
| 문제은행 | `bank_questions`. 기출 전역 공용(학원 경계 없음) |
| 평가 세트 | 강사가 엑셀/CSV로 올리는 학원 평가. 1인 1회 응시 + 전자서명 |

## 2. 사용자 역할

| 역할 | 진입·착지 | 가입 | 권한 요약 |
|---|---|---|---|
| 학원장 `admin` | `/admin` | 학원 개설 코드 + 아이디 | 학원 요약·학생 참여·강사 관리·수강평 실명·학생 정보 |
| 강사 `teacher` | `/teacher` | 전역 코드 또는 원장 초대 링크 | ROOM·자료·수업·과제·게시판·출제·평가·인사이트·리포트 |
| 학생 `student` | `/ask` | 이름·아이디·휴대폰 (+초대 코드) | 질문·수업·과제·문제풀이·기출·마이페이지 |
| 개발자 `dev` | `/dev` | 운영자 계정 | 서비스 전체 지표 |

계층: 학원(원장) → 강사 → 학생. 원장이 강사를, 강사가 학생(ROOM)을 초대한다. 착지는 서버 `profiles.role` 기준(`homeFor`).

**ASK-03 상세** (`src/app/api/ask/route.ts`)

- 선행조건: 로그인 + 같은 학원 강사
- 입력: 질문, 강사 ID, (선택) 강좌 ID·대화 ID
- 처리: ① `requireUser`(401) ② 계정당 분당 20회 ③ `sameAcademy`(다른 학원 404) ④ 대화 소유권 확인 ⑤ 강사 조회 + 검색(강사 자료 `match_chunks` + 공용 법령 `match_reference_chunks`) + 대화 이력을 `Promise.all` 병렬 ⑥ 시스템 프롬프트 조립 — 강사 자료와 법령을 **섹션 분리**, "기출 해설과 다르면 출제 당시 / 현행 기준으로 나눠 설명" ⑦ conversation을 스트리밍 **전에** 만들어 `X-Conversation-Id`·`X-Sources` 헤더로 전달 ⑧ `ReadableStream` 스트리밍(enqueue try/catch — 클라이언트가 끊어도 진행) ⑨ 종료 후 `messages`·`message_citations` 기록(실패해도 답변 무영향)
- 예외: 강사 자료 근거 없음 → 일반 지식으로 답하되 자료 부족을 밝힘 / LLM 키 없음 → 검색 결과 미리보기만 / 임베딩 실패 → lexical 폴백(법령은 제외) / 429 → 한국어 안내

## 5. 핵심 동작

### 5.1 자료 파이프라인

```
텍스트 입력 또는 PDF 업로드
  → (PDF) unpdf 텍스트 추출, 비면 LLM 비전 OCR (Gemini → Anthropic, 15MB)
  → chunkText() — 문단 → 문장 → 글자 순으로 쪼개 800자/겹침 150 그리디 병합
  → embedMany() 배치 임베딩 (실패 시 문서 행 롤백)
  → documents(원본) + chunks(조각+embedding) 저장 → document_events 감사 로그
  → (수업 자료면) summarizeLesson() → documents.summary
```

### 5.2 검색

- 강사 자료: pgvector `match_chunks`(강사·강좌 필터, 공용 자료 항상 포함, 말투 자료 제외) top-5
- 공용 법령: `match_reference_chunks` 별도 호출 → 유사도 0.68 이상 2건만 뒤에 붙임. 한 순위표에 섞으면 조문이 강사 자료를 밀어낸다. 임계값은 질문 33개 실측(`법령-참고자료.md`)
- 임베딩 불가 시 강사 청크 최대 500개 lexical 랭킹(`lib/lexical.ts` — 한국어 2-gram + 토큰 일치). 법령은 폴백에 넣지 않음

### 5.3 프로바이더 폴백 체인

교체 시 해당 lib 파일 하나만 고치면 되도록 격리돼 있다.

| 기능 | 우선 | 폴백 | 전무할 때 |
|---|---|---|---|
| 답변 생성 (`lib/anthropic.ts`) | `ANTHROPIC_API_KEY` | `GEMINI_API_KEY` (429면 flash-lite로 1회 재시도) | 생성 생략, 검색 결과만 반환 |
| 임베딩 (`lib/embed.ts`) | `OPENAI_API_KEY` | `GEMINI_API_KEY` (3072→1536 MRL 축소+정규화) | `null` → lexical |
| 검색 (`lib/retrieve.ts`) | pgvector RPC | lexical 랭킹 | — |
| OCR (`lib/ocr.ts`) | `GEMINI_API_KEY` | `ANTHROPIC_API_KEY` | 422 안내 |

임베딩 차원은 `vector(1536)` 고정 — 바꾸면 스키마와 기존 데이터 전부 재작업.

### 5.4 노출 규칙 (학생)

teachers·courses·lessons·board·submissions 전부 **"수강 연결된 것 + 공용(course_id null)"**만. 강사·원장은 학원 전체. 새 학생용 API도 이 규칙을 따른다.

### 5.5 문제은행 데이터

- 원본: comcbt 게시판의 기출 PDF·HWP → acct_quiz 파이프라인(`parse_questions.py`·`parse_comhwal.py`) → `questions.json` → `scripts/import-bank.ts`
- upsert 키 `(source, stem)`. 지문을 고칠 땐 `update-bank-stems.ts`로 **id 보존** 교체 — 갈아끼우면 오답노트·시험 기록이 끊긴다
- 정리(삭제) 단계는 소스에 든 과목만 대상 — 한 과목만 담긴 산출물로 전 과목이 지워질 뻔한 사고 이후
- 그림: 지문 아래 큰 그림은 `images` 컬럼, 글 속 그림은 `[[그림]]URL#폭x높이` 토큰(Storage `bank-images`)
- 상세·함정: `문제은행-적재-규칙.md`

### 5.6 PWA

- `manifest.ts` — `start_url: /`, `display: standalone`. 아이콘은 `next/og` 동적 생성(레포에 바이너리 없음)
- iOS 16.4 미만은 `start_url`을 무시하고 추가하던 순간의 URL을 박는다 → 안내 화면에 "앱 화면 열기"(`/`) 버튼을 두고 거기서 추가하게 함
- Android는 `beforeinstallprompt`로 설치 버튼, iOS·삼성 인터넷·인앱 브라우저는 수동 안내

## 9. 알려진 한계·백로그

**답변 품질**
- 강사 자료에 유사도 하한이 없다 — 무관한 자료도 top-5가 근거로 들어간다 (법령만 0.68 하한)
- 강사 자료 0건이면 일반 지식으로 답한다(자료 부족은 밝힘)
- `max_tokens` 1200 고정(긴 답변 잘림 알림 없음), 맥락 10개 고정, 중단해도 서버는 끝까지 생성

**데이터**
- 컴활 해설 없음, 2013~2016년 문항은 Windows 7·엑셀 2010 기준
- 실무는 전표·결산만 (부가세신고서·원천징수·법인조정은 KcLep 조작형이라 제외)
- 소득세법 시행령 적재 미완 (ASK-13)

**백로그 (결정 대기 포함)**
- Discord 알림 — 코드 완료(INS-09), 웹후크 URL 대기. 하루 첫 접속·CBT 채점·신규 가입 알림은 미적용
- 문제은행 단독 배포(익명 풀이) — 한국세무사회 기출 저작권 확인이 선행 조건
- 과제 사진 제출, 초대 코드 회전(스키마 `invite_version` 필요), 약관 동의 기록 저장(`terms_agreed_at`)
- 원장의 강사 완전 제거 — 학생 학습 기록까지 cascade 삭제되는 스키마라 "소속 해제" 방식 결정 필요
- 이미지 자료, 부분 스캔 PDF OCR, 페이지 단위 OCR, `documents.source`에 hwp/docx 구분
- rate limit 공유 저장소(다중 인스턴스) — 요금제 한도가 빠져 LLM·임베딩 비용 방어가 rate limit뿐이다
- e2e 휴대폰 가입 2건 원인 확인
