# 문제은행 적재 규칙

기출문제를 `bank_questions`로 가져올 때 지켜야 하는 규칙. 어기면 "125회 (22문항)"이라
보여놓고 실제론 문제가 빠져 있는 식의 불일치가 생긴다 (2026-08-19 실제 발생 → 수정).

## 시험 구조 (정답 기준)

| 과목 | 이론 (4지선다) | 실무 |
|---|---|---|
| 전산회계 1·2급 | **1~15번, 15문항** | KcLep 프로그램 작업 (분개·결산 등) |
| 전산세무 1·2급 | **1~15번, 15문항** | KcLep 프로그램 작업 |
| 컴활2급 (필기) | **1~40번, 40문항** (1~20 컴퓨터 일반 · 21~40 스프레드시트 일반) | 없음 (실기는 별도 시험) |

- **회차당 이론은 반드시 15문항**이다(컴활2급은 40). 적재 후 모자라면 파이프라인 유실이다.
- 실무 문항 수는 회차·급수마다 다르다 (고정 아님).

## 데이터 규칙

1. **이론 = `category: "이론"` + `choices`(4지선다) + `answer_idx`**
   - 이론 파트의 분개 유형 문제도 4지선다면 이론이다. 답이 분개 텍스트(`answer_text`)인
     것만 실무로 분류한다.
   - 실무 분류 (v0.39.0, acct_quiz `parse_questions.py`의 문제 헤더 키워드로 결정):
     - **전산세무\***: `일반전표` / `매입매출전표` / `결산` 3분류
     - **전산회계\***: `일반전표` / `결산` 2분류 — 회계의 매입매출전표 문제는 정책상 제외
     - **전산세무1급 문제1은 섹션 지시문으로 못 가른다** — 일반전표·매입매출전표를 한
       문제에 섞어 내고 지시문은 "다음 거래에 대하여 적절한 회계처리를 하시오"뿐이다.
       항목별 `[답]` 첫 줄(`일반전표입력`/`매입매출전표입력`)로 가른다. 표기가 회차마다
       흔들린다: `매입매출입력`(114회) · `매출매입전표입력`(111회 오타) · 종류 없이
       날짜만(86회) · 종류도 날짜도 없이 바로 `유형:` 줄(123회).
     - 지시문 키워드는 **"< 입력 시 유의사항 >" 앞까지만** 본다. 그 뒤 공통 안내문에
       "매입매출전표를 입력하는 경우…"가 들어 있어, 넓게 읽으면 일반전표 문항까지 통째로
       매입매출으로 뒤집힌다 (108·112~115·126회가 그랬다)
     - 실무 문항은 **전 회차 추출 가능** (2026-08-25). PDF 확정답안(108·111~125)은
       `parse_practical`, 구회차 HWP 답안(86~110)은 `parse_hwp_practical`이 맡는다.
       - 한때 "구회차는 자동번호 소실로 실무 파싱 불가"로 두었으나, 실제로 사라지는
         건 문항번호뿐이고 본문·`[답]`·분개표는 남아 있다. 배점 `(3점)` 표기와
         `[답]` 마커로 문항을 자른다 (86~98회는 `[1]` 번호가 살아 있어 그쪽 우선).
       - 섹션 분류는 `문제N` **바로 앞 지시문 한 줄**로만 판단할 것. 앞쪽을 넓게
         훑으면 직전 섹션의 분개표가 섞여 조작형(부가세 신고·원천징수)까지 실무로
         잘못 들어온다.
1-1. **영역(area)은 급수 시험범위 안에서만 분류한다** (`ALLOWED_AREAS`) — 범위 밖 규칙은
   건너뛴다. `법인세`는 **전산세무1급 전용**이고, 태그 규칙은 `익금`·`손금`·`세무조정`처럼
   다른 영역과 겹치지 않는 말로만 잡아 규칙 목록 맨 앞에 둔다(뒤에 두면 감가상각 시부인·
   기업업무추진비 한도 문제가 재무회계 태그로 먼저 먹힌다). `법인세` 단독 단어는 규칙에서
   빼야 한다 — 재무회계의 법인세비용·이연법인세가 끌려온다.

2. **`source`는 `"<과목> <회차>회"` 형식** (예: `전산회계2급 125회`). 회차 CBT·회차
   드롭다운이 이 문자열을 그대로 쓴다.
3. **중복 키는 `(source, stem)`** — stem 단독이 아니다.
   - 기출은 같은 문제가 여러 회차에 재출제된다. stem 단독 unique면 재출제 문제가
     첫 회차에만 남아 뒤 회차 CBT가 빈다 (125회 이론 3개가 122·119·112회에 흡수됐던 사고).
   - DB 제약: `bank_questions_source_stem_key` = `unique nulls not distinct (source, stem)`
     (마이그레이션 `20260819040000`). `import-bank.ts`의 dedup·upsert 키도 동일.
4. **회차 문항 수 집계(`bank_source_counts` 뷰)는 이론만 센다** — CBT가 이론만 출제하므로
   실무를 합산하면 "22문항"이라 보여주고 15문제만 나오는 착시가 생긴다
   (마이그레이션 `20260819030000`).
5. 회차를 골라 시작하면 **그 회차 이론 전체**를 원래 순서로 출제한다 (`limit=50`,
   문항 수 선택은 랜덤 출제 전용).

## 적재 절차

```bash
# 1. 원본 수집 (acct_quiz 파이프라인 — 게시판 h1=회계1급 h2=회계2급 h3=세무2급 h4=세무1급)
#    python fetch_comcbt.py --board h4 --from 86 --to 126
# 2. 파싱 → 소스 산출물 C:\dev\acct_quiz\pipeline\out\questions.json
#    PYTHONIOENCODING=utf-8 python parse_questions.py
# 3. 적재 (재실행 안전 — (source, stem) upsert)
npx tsx scripts/import-bank.ts          # BANK_SRC=<경로> 로 소스 지정 가능
# 4. 스크립트 끝에 나오는 "이론 15문항 미만 회차" 경고 확인
```

⚠️ **정리(삭제) 단계의 범위**: import-bank는 "소스에 없는 옛 행"을 지운다. 이 정리는
**소스에 들어 있는 과목만** 훑는다 — 한 과목만 담긴 산출물(예: 세무1급만 파싱한
questions.json)로 돌릴 때 전 과목을 훑으면 나머지 과목이 통째로 지워진다.

`seq`(시험지 문항번호)는 파서가 이론 문항에 채워 내보내고 import-bank가 그대로 넣는다 —
회차 CBT 출제 순서가 여기 달려 있으니 새 파서 경로를 만들면 seq도 같이 채울 것.

## 표(테이블) 적재 — 표준 (⚠️ 같은 실수 방지)

**사고 (2026-08-19)**: 전산세무2급 86회 8번 원가 문제 — HWP 파서가 표 구조를 버리고
셀 텍스트를 위→아래로 흘려서, 웹에서 표가 세로 나열(`사용/제공/보조부문/S1/0/0.2/…`)로
깨져 보였다. 표는 이미지가 아니라 **선+텍스트**라 이미지 스캔으로도 안 잡힌다.

규칙:

1. **HWP 소스(구회차)**: `hwp_importer._consume_table`이 셀 좌표(LIST_HEADER col/row)로
   구조를 복원해 **`[[표]]셀|셀∥셀|셀[[/표]]` 한 줄**로 직렬화한다 (행 `∥`, 셀 `|`).
   - **중첩 표 주의**: 기출 자료는 "박스(1×1 표) 안에 진짜 표"가 흔하다 — 재귀 처리
     없이는 안쪽 셀이 통째로 유실된다 (86회가 정확히 이 케이스)
   - **보기(①~④)를 표로 조판한 회차**(107·109·110회 등)는 직렬화하면 보기 파싱이
     깨진다 — 글리프가 보이면 예전처럼 문단 줄로 흘린다 (`is_choices` 폴백)
   - **정답표도 표가 된다** — `parse_questions._untable`이 정답표 구간만 도로 풀어
     해석한다. 이걸 빼먹으면 "A형 정답표 0개" 실패로 회차가 통째로 빠진다
2. **PDF 소스(최근 회차)**: 텍스트 추출로는 표 구조를 못 살린다 —
   `extract_images.py`가 `find_tables()`로 표 있는 문제를 찾아 **영역 캡처**(이미지 절차와
   동일)로 보완한다. stem 텍스트는 그대로 두고 그림을 곁들이는 방식
3. **웹 렌더**: `BankQuestion.tsx`의 `TableBlock`이 `[[표]]` 직렬화를 HTML 표로 그린다
   (stem·해설 공통). 셀 텍스트에 `|`·`∥` 문자가 들어가면 깨진다 — 회계 기출엔 사실상
   없지만, 파이프라인에서 새 직렬화 문자를 쓰게 되면 여기와 함께 바꿔야 한다
4. **stem이 바뀌는 재파싱 후엔 반드시 `scripts/update-bank-stems.ts`** (dry-run → `--apply`)
   — import-bank의 (source,stem) upsert는 stem이 바뀌면 **새 행**을 만들어 오답노트
   기록(question_id)이 끊긴다. update-bank-stems가 표·공백을 벗긴 글자 키로 매칭해
   **id를 보존한 채** stem·해설만 교체한다

## 그림 자료(이미지) 적재 — 표준

문제에 딸린 그림(현금영수증·사업자등록증 같은 증빙)은 텍스트 적재에서 빠진다.
아래 2단계로 붙인다 (125회로 검증한 절차, 2026-08-19):

1. **추출 (acct_quiz)** — `pipeline/extract_images.py`
   ```bash
   python extract_images.py --pdf "raw/제111회 전산회계2급 A형.pdf" --source "전산회계2급 111회"
   # → out/images/<source>/q_p<페이지>_<n>.png + <source>.json
   ```
   - **임베디드 이미지가 아니라 "문제 영역 렌더 캡처"**를 쓴다. PDF 속 증빙은
     표+텍스트+로고 이미지의 합성이라 이미지만 뽑으면 로고 조각(KICC 로고 등)만 나온다.
     문제 문장 끝 ~ 선택지(①) 시작 구간을 2배 해상도로 잘라야 사람이 보던 그림이 나온다
   - 장식(머리글·꼬리글 로고, 반복 xref, 괘선)은 자동 필터
2. **적재 (acct_rag)** — `scripts/import-bank-images.ts`
   ```bash
   npx tsx scripts/import-bank-images.ts "전산회계2급 111회"   # 인자 없으면 전체
   ```
   - Supabase Storage `bank-images`(public)에 업로드 — 키는 ASCII 슬러그
     (`전산회계2급 111회` → `ca2-111/…`, 한글 키는 Storage가 거부)
   - 캡처의 문제 첫 문장(공백 제거 25자)으로 같은 source의 stem을 찾아
     `bank_questions.images`(jsonb, URL 배열)에 연결. 매칭 실패는 경고로 남는다
   - 재실행 안전 (upsert + URL 중복 제거)
3. 화면은 `StemView`가 `images`를 받아 본문 아래 렌더 (공부·한 문제씩·CBT·오답노트 공통)

**현황 (2026-08-19 전 회차 스캔 결과)**: A형 PDF 47개 중 이론부에 그림 자료가 있는
회차는 **111회·118회(전산회계2급) 단 2개** — 둘 다 현금영수증 증빙, 적재 완료.
125회는 이론 그림 자료 없음 (표·자료는 전부 텍스트로 이미 stem에 있음. 실무 파트의
사업자등록증 이미지는 DB에 없는 프로그램 작업 문제 소속이라 제외).
새 회차 추가 시 extract_images.py를 돌려 캡처가 나오면 2번으로 적재하면 된다.

## 구회차 HWP 실무 파싱 — 표준 (2026-09-21)

구회차 HWP는 문항 자동번호가 추출에서 소실된다 — `[1][2][3]`이 없다. 본문·`[답]`·분개표는
남아 있으므로 `parse_hwp_practical`이 이렇게 자른다:

1. 섹션(문제N) 분류는 **`문제N` 바로 앞 지시문 한 줄**로만 판단한다. 앞쪽을 넓게 훑으면
   직전 섹션의 분개표가 섞여 조작형(부가세 신고·원천징수·법인조정)까지 딸려 들어온다.
2. 머리글 정규식은 **꼬리 낱자·모음을 허용**해야 한다(`문제2ㅔ` — 세무1급 99회). 놓치면
   그 섹션이 앞 섹션 본문으로 흡수돼 조작형 문항이 전표로 들어온다.
3. 문항 경계: `[N]` 번호가 살아 있으면 그쪽(86~101회), 없으면 **배점 `(N점)` 줄**을 문항
   시작으로 본다(102~111회). stem = 지시문 + 뒤따르는 자료(`[[서식]]`), 배점 표기는 뺀다.
4. 정답이 통째로 `ㆍ` 목록인 결산 문항이 있다(106회) — 첫 줄부터 `ㆍ`면 해설로 떼지 말 것
   (떼면 answer_text가 비어 그 문항이 통째로 사라진다).

## 컴활2급 (컴퓨터활용능력 2급 필기) — 2026-10-08


규칙:

1. **소스는 comcbt `c2` 게시판의 교사용 PDF**(정답이 ❶~❹로 채워져 있다). 마지막 쪽 정답표와
   교차 확인하고 다르면 정답표를 따른다(2026-10-08 기준 800문항 전부 일치).
   - **해설집은 받지 않는다** — comcbt가 해설집에 "문서의 수정 및 DB 저장, 기타 금전적 이익을
     취하는 일체의 행위를 금지"를 명시했다. 그래서 컴활 문항은 `explanation`이 비어 있다
2. **`source` = `"컴활2급 <연도>년 <회>회"`** (예: `컴활2급 2020년 2회`). 회차가 해마다 1회부터라
   통산 회차가 없다. 파일명엔 날짜만 있어 **그 해 시행 순번**으로 회차를 매긴다 — 한 해 PDF를
   일부만 받으면 순번이 밀리니 연도 단위로 전부 받을 것. 화면(`/bank` 회차 드롭다운)은
   연도까지 보고 정렬·표기한다(`roundKey`/`roundLabel`) — 숫자 하나만 뽑으면 "2회"가 여덟 개 생긴다
3. **영역(area)** = `컴퓨터 일반`(1~20번) / `스프레드시트 일반`(21~40번). **유형(type_tag) = 파트(part)**
   — 키워드 점수로 분류(Windows·네트워크·하드웨어… / 수식·함수·차트·데이터 관리…). 문제검색에서
   영역을 고르면 파트 뱃지로 나온다
4. **PDF는 2단 조판 + 글 중간에 박힌 그림**(아이콘 "경고( 🛈 )", 수식 결과 "=MID(…) → [그림]",
   보기 자체가 그림 — 2×2 배치도 있다). 줄이 아니라 **행**(같은 높이의 글 조각+그림, x 순)으로 읽는다
   - 글 속 그림은 토큰 **`[[그림]]<경로>#<폭>x<높이>`**(PDF pt)로 제자리에 남긴다. `import-bank.ts`가
     그림을 Storage(`bank-images/cu2-<연도>-<회>/…`)에 올리고 경로를 공개 URL로 바꿔 넣는다.
     화면은 `BankQuestion`의 `Hi`가 토큰을 그림으로 그린다(지문·보기·표 칸 공통)
   - 글 없이 그림만 있는 행은 지문 쪽이면 `images`(지문 아래 그림), 보기 쪽이면 앞 보기의 이어지는 부분
   - 보기 그림은 "왼쪽에 있는 번호 중 **가장 가까운 것**"에 붙인다 — 첫 번호에 붙이면 2×2 배치에서 ②·④가 빈다
5. **줄 잇기**: 줄바꿈이 낱말 중간에서도 일어난다("압" / "축률"). 낱말 경계면 앞줄 끝에 공백이
   남아 있으므로 **그대로 이어 붙인다**. 번호 뒤 들여쓰기는 번호 폭만큼이라 "1. "은 +12pt, "10. "은
   +17pt — 하나로 고정하면 1~9번 지문이 줄마다 끊긴다. 단을 넘어가면 단 왼쪽 여백 기준으로 다시 잰다
6. **과목 머리글 "2과목 : 스프레드시트 일반"은 버린다** — 안 거르면 20번 마지막 보기 끝에 붙는다
7. **한 회차에 지문이 똑같은 문항이 있다**(2014년 3회 30·36번 "다음 중 수식의 실행 결과가 옳지 않은
   것은?" — 보기만 다르다). DB 키가 `(source, stem)`이라 뒤 문항이 앞 문항을 덮는다. 문구는 그대로 두고
   **지문 끝에 보이지 않는 ZWSP(U+200B)**를 붙여 가른다(JS `trim()`도 지우지 않는다)
8. `import-bank.ts`는 소스에 `part`·`images` 키가 **있을 때만** 그 컬럼을 싣는다. 회계 산출물엔 없는
   키라, 무조건 실으면 따로 백필한 소득세 파트·증빙 그림이 NULL로 덮인다

알려진 한계: 2013~2016년 문항은 Windows 7·엑셀 2010 기준이다. comcbt가 "(윈도우 10 검증 완료)"를
단 문항만 현행과 맞는 것이 확인됐고, 나머지는 현행 출제 기준(Windows 10·엑셀 2021)과 다를 수 있다.
